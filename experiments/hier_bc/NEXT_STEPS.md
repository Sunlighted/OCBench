# 后续研究方向记录（2026-11-02）

基于 `RESULTS.md` 的结论整理。按优先级排序；A 为当前重点，B、C 暂缓。

## A. 演示来源对 BC → RL 微调的影响（当前重点）

问题：用“仿人类”轨迹训练的 BC 做 RL 微调，与用 planner / RL agent 生成的轨迹训练的 BC 做 RL 微调，有什么不同？

- 任务：block-single、block-double（短时程，便于大量 RL 实验）。
- 数据变体（同一脚本控制器，逐个打开“人类特征”）：
  干净（`p_mistake=0`、固定快速度、无噪声，≈ planner）→ 加速度差异 → 加动作噪声 → 加犯错与纠正（默认 OCBench 数据）；
  另加 RL agent 数据（由收敛的 RL 策略 rollout 得到）。
  已实现：`impls/demo_variants.py`（`--traj_noise` 0–1 缩放 primitive 轨迹随机性与方块顺序，`--speed_profile`，`--p_mistake`）。
  OCBench 默认 = traj_noise 1、speed 0.7–1.5、p_mistake 0.1。BC 只用 50–100 条演示。
  第一批（每种 100 条成功演示，node5 `~/exp/demos/block-{single,double}-task1/`）：

  | 变体 | traj_noise | speed | p_mistake | single 长度 均值±std（成功率） | double 长度 均值±std（成功率） |
  |---|---|---|---|---|---|
  | v0_planner | 0 | 1.0 固定 | 0 | 533±123 (100%) | 1257±214 (97%) |
  | v1_speed | 0 | 0.7–1.5 | 0 | 575±181 (100%) | 1339±342 (98%) |
  | v2_traj | 1 | 1.0 固定 | 0 | 622±176 (98%) | 1530±270 (99%) |
  | v3_traj_speed | 1 | 0.7–1.5 | 0 | 658±217 (97%) | 1553±390 (90%) |
  | v4_ocbench | 1 | 0.7–1.5 | 0.1 | 657±210 (85%) | 1604±381 (80%) |
- BC prior：确定性 BC（L2）与 flow BC。
- 微调方法：
  - 确定性 BC：残差 RL、RLPD（演示放入 buffer）、IBRL。
  - flow BC：残差（EXPO）、噪声空间 steering（DSRL）、基于 Q 的采样选择（Best-of-N 等）。
- 奖励：成功（稀疏）+ 时间惩罚，使微调目标包含演示没有优化的部分（速度、精度）。
- 指标：
  - 初始成功率 J(π0)、达到给定成功率所需交互步数、最终成功率与完成用时。
  - prior 的“可改进空间”：动作熵、π0 样本上的 Q 值离散度 σ_Q、微调后策略相对 π0 的支撑覆盖。
- 核心假设（见对话中的数学分析）：
  - steering 类方法的提升上界由 π0 的支撑与多样性决定。窄的 planner prior 起点高、提升空间小；宽的人类 prior 反之。
  - 残差类方法只能做局部修正。
  - RLPD 的收益取决于数据对最优策略状态分布的覆盖。

## B. 短时程指令条件执行：少量演示 BC → RL（暂缓，A 的推广）

- 子任务环境：
  - 把仿真重置到数据集中任意子任务片段的起点（数据含 `qpos/qvel/dynamics_info`），给一条子目标指令，用控制器 `_subtask_success` 判定成功并记录用时。
  - 各环境 `set_state` 签名不同：基类 `(qpos, qvel)`、hanoi `(qpos, qvel, dynamics_info)`、chamber `(qpos, qvel, dynamics_info, button_states)`、switch `(qpos, qvel, button_states)`。
  - 需先验证重置后观测与数据一致，以及 task_info / 随机布局能被恢复。
- 演示数量：每类子任务 N ∈ {10, 50, 200, 1000, 全部}。另研究演示质量（`speed`、犯错片段）。
- 动机：分层 BC 执行器“慢”是 block/chamber/switch 的主要瓶颈（×4 时间仍大幅上涨），正是 RL 应解决的问题。
- 工程：TPU 节点不能跑 mjwarp（需 CUDA），在线 RL 用 CPU 并行环境（240 vCPU）。ResMLP 4096×8 的 RL 更新速度需实测。

## C. 长时程：VLM 推理器 + 指令执行器（暂缓）

- 把端到端失败拆成感知 / 推理 / 调用时机 / 执行四类误差，用 oracle 逐个替换来隔离。
- 实验 1（无需 VLM）：oracle 高层下的调用方式对比，即每 chunk / 每子任务 / 失败时重规划 / 只在开头规划一次（开环）。
- 实验 2（无需 VLM）：模拟规划延迟（同步等待 vs 异步执行）。
- 实验 3：VLM 2×2 设计，输入（特权状态文字 vs 图像）× 输出（直接 vs 推理链），加上零样本 vs 微调；难度轴为方块数、圆盘数、开关网格大小。
- 前置：执行器接口从特权坐标改为符号化指令；修复 TPU VM 上的渲染（EGL 崩溃）。
- 已知证据：
  - 叠放任务约 40% 的上层超时发生在塔被碰倒之后，说明完全开环很脆弱。
  - hanoi 需要全量数据（1 shard 1.6% → 10 shard 17%）。

### A 的第一批 RL 结果（block-single-task1，2026-11-02，`impls/rl_prior.py`）

设置：prior 冻结；chunk 级 critic（25 步 × 7 维），奖励 −0.04/步、成功为 0；batch 中演示/在线各半；50 万环境步；最终评估 500 个 episode（x1）。3 个种子，表中为均值。

- Best-of-N（N=32，flow BC prior）：所有变体提升都在 0 到 2.5 个点（噪声内）。预热后的 critic 在上线时会让 n100 的 v0/v1/v4 低于 prior。
- Residual（边界 0.2，L2 正则 λ=0.03；pilot 中 λ=0.01 会把 v0 改坏）：

  | prior | v0 planner | v1 speed | v2 traj | v3 traj+speed | v4 ocbench |
  |---|---|---|---|---|---|
  | BC n100：prior → RL | 39.8 → 39.3 (−0.5) | 32.7 → 34.3 (+1.6) | 26.7 → 34.1 (+7.4) | 27.4 → 33.6 (+6.2) | 26.0 → 32.1 (+6.1) |
  | flow BC n100：prior → RL | 39.7 → 41.6 (+1.9) | 34.5 → 37.7 (+3.2) | 24.5 → 26.8 (+2.3) | 25.5 → 31.6 (+6.1) | 20.1 → 24.9 (+4.9) |

  - 演示中有轨迹噪声的 prior（v2–v4）提升明显更大，且在 3 个种子上都为正；planner prior 几乎不变。差距从约 13 个点缩小到约 6 个点。
  - 成功轨迹的用时没有缩短（|Δ| 约 0.02，residual 只做很小的修正）。

### 把 RL 在 block-single 上调上去（2026-11-03 至 11-04）

v0 和 v4 用 n100 的确定性 BC prior（v0 39.2%，v4 22.4%），每个 100 万步，最终评估 500 个 episode。

| 方法 | 结果 | 原因 / 备注 |
|---|---|---|
| RLPD（25 步动作块，从零开始或 BC 初始化） | 1% 到 11% | BC 初始化的 std 被熵目标强行抬高，第一轮就崩；critic 初期高估（Q 为正）；从零开始几乎采不到成功 |
| TD3+BC 微调整个 prior（BC 权重 3 到 100，actor 学习率最低 1e-6，目标截断到 ≤ 0） | 一上线就降到约 0% | 只要 actor 跟着 ∇ₐQ 更新就崩，只做 BC 时稳定。175 维动作块上的 critic 梯度基本是对抗方向 |
| AWR（critic 只给数据加权） | v0 46%，v4 约 32% | 稳定，但很快到平台 |
| 按成功筛选的自模仿（`--self_imitation --q_weight=0`） | v0 54%，v1 49%，v2 49%，v3 45%，v4 47% | 所有变体都提升；v4 涨得更多（+25），起点差距缩小到约 7 个点；之后在约 50% 停住 |

- 每次执行的步数：同一个 prior 执行 5、10、25 步的成功率分别是 10%、24.5%、39%，频繁重规划会让策略在不同模式之间切换。
- 演示的初始布局：`demo_variants.py` 用递增的 reset seed（0、1、2……）收集演示，所以 BC 在训练布局（seed 0–99）上的成功率是 96%，在随机布局上只有约 37%。
- 失败模式（v0，200 个随机布局，见 `failure_diag.py`）：约 60% 的 episode 没有抓起方块。在这些 episode 里，夹爪到达了方块附近（中位距离 1.6 cm）并发生了接触，82% 把方块推动了超过 2 cm，然后夹爪合上却没有夹住东西，保持约 300 步，不会张开重试。
  - 失败和初始的方块位置、朝向基本无关。
  - 主要原因是抓取精度不够，加上抓空后不会恢复（planner 演示里没有重试动作）。
  - 自模仿只能学到原本就能成功的抓取，学不会恢复，所以停在约 50%。
